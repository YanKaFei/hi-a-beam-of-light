## 1. 风险登记表

等级：可能性 × 影响。**S1** 影响产品正确性/可发布性｜**S2** 影响进度｜**S3** 可控

| ID | 风险 | 等级 | 可能性 | 影响 | 缓解 |
|---|---|---|---|---|---|
| R-01 | **模型家族被过度计数**，用户直接看到错误称号/错误深红 | **S1** | 高（已实测发生） | 产品可信度崩塌 | 注册表查表 + `UNKNOWN` 不猜 + fixtures 锁边界（[G-02](02-requirements-traceability.md)） |
| R-02 | **适配器越界读取用户内容**，形成隐私事故 | **S1** | 中 | 致命，不可挽回 | 列级 allowlist + CI 断言 + 代码评审强制（[G-01](02-requirements-traceability.md)） |
| R-03 | 无 Xcode/Android SDK/AppID，F5 整体无法推进 | **S1** | 确定 | V1.0「六端」承诺无法兑现 | 把 F5 明确标 BLOCKED，F0–F4 先做完整可交付的单主路径 |
| R-04 | NFC 真机行为与文档预期不符（后台读取条件苛刻） | **S2** | 中 | A08 无法验收 | 验收定义为「打开 HTTPS 页面」，二维码永远并列（[G-13](02-requirements-traceability.md)） |
| R-05 | crates.io 不可达，他人/CI 构建失败 | **S2** | 确定 | 项目无法交接 | 镜像配置入仓 + `.cargo/config.toml` + 文档；关键依赖考虑 vendor |
| R-06 | 撤回承诺无法兑现（聚合已固化 identity 痕迹） | **S1** | 中 | 失信 + 合规风险 | 聚合表物理上无 identity 列 + 删除后重算（[G-09](02-requirements-traceability.md)） |
| R-07 | 传光称号被刷量（100 个节点成本过低） | **S2** | 高 | 称号失去意义 | 24h 冷却 + 同源降权 + 每日会话上限（[G-11](02-requirements-traceability.md)） |
| R-08 | 「E2 不计入称号」导致移动/小程序用户永远「寻光者」 | **S1** | 高 | 整端体验像 bug | 需决策 D-04：光种恢复继承 or E2 仅本地显示（[G-19](02-requirements-traceability.md)） |
| R-09 | 桌面常驻内存/CPU 超 SLO（<120MB / <1% CPU） | **S2** | 中 | 用户卸载 | Canvas2D 优先、WebGL 仅光场、悬浮窗极小、真机实测门禁 |
| R-10 | Tauri 透明窗在 macOS 27 有系统级回归（新系统） | **S2** | 中 | 核心形态失效 | F2 第 1 天就做最小可运行窗口（T-01），而不是最后做 |
| R-11 | 品牌名未定，后期改名成本扩散 | **S3** | 中 | 返工 | 代码用 `firstlight`，品牌串单点配置（ADR-006） |
| R-12 | 合规（备案、隐私政策、未成年人）缺失导致无法上架 | **S1** | 中 | 无法发布 | 需运营主体；F6-08；尽早咨询合规 |
| R-13 | 我方自行推断"用户已使用"，违反核心原则 | **S1** | 中 | 违反产品精神 | 证据等级硬约束（DB CHECK）+ A02/A05/A09 用例锁死 |
| R-14 | 空状态被"好看的数据"填充（造假诱惑） | **S1** | 中 | 违反 §8.5 | 接口层无数据即返回空 + 测试断言不得 mock 生产数据 |
| R-15 | 三端协议漂移（TS/Rust 各自演化） | **S2** | 高 | 静默不一致 | 共享 fixtures 双向测试（F1-11） |

## 4. 四类「绝不能做」的红线（来自总控指令 §八，逐条落成检查项）

| 红线 | 检查手段 | 检查时机 |
|---|---|---|
| 不用模拟数据冒充真实 | 生产接口无数据即空状态；测试数据必须标记 `fixture` | 每次演示前 |
| 不用截图冒充真机 | [07 §4](07-device-matrix.md) 记录规范 | 每次升级状态 |
| 不把 API 配置当真实调用 | A05 用例 + `usage_event` 只收 E3/E4 | F2 验收 |
| 不把扫码当传光成功 | A07 用例 + 门控函数 | F3 验收 |
| 不把安装当真实用户 | A01 + A09 用例 | F2 验收 |
| 不授权扫描全盘 | 路径白名单 + 授权门 + 日志可查 | F2 验收 |
| 不上传 Key/提示词/聊天 | 请求 schema `additionalProperties:false` + CI 注入测试 | F1/F3 |
| 未测试不得标已集成 | 状态口径表 | 每次提交 |
| 不得跳过核心校验让测试通过 | 评审红线 | 每次 PR |
| 每个里程碑提供可重复命令 | `docs/test-report.md` | 每个里程碑 |

## 5. 风险总评

最高风险的三个不是技术风险，而是**产品正确性风险**：

1. **R-01 家族过度计数**：已经用真实数据证明会发生。这是最快毁掉产品可信度的一件事——
   用户会立刻发现"我只用了一个模型，为什么是全服最高称号"。
2. **R-08 移动端称号卡死**：程序上正确，体验上是 bug。必须靠产品决策解决。
3. **R-02 适配器越界读取**：一次事故就永久毁掉"我们不读你的内容"这个承诺。

技术风险（Tauri/性能/实时）都在可控范围，因为 F0 已经用真实构建和真实数据把它们从"假设"变成了"已知"。

|---|---|---|

**修复前**：页脚两个链接宽 **37px**（<44）。
**修复**：`.link` 增加 `min-width: 44px` 与水平内边距。
**修复后复测**：`BELOW_44: []`。

## 2. 找到并修掉的根因：rpx 字号在窄屏会缩小

rpx 与屏宽成正比：`20rpx` 在 390px 上 ≈ 10.4px，**在 320px 上只有 8.5px**——
小字阶会不可读，而且这是设计时看不出来的。

**修复**：把全部字号从 rpx 改为 **px**（24 处声明），排版节奏仍用 rpx。
效果：字号不再随屏宽变化，320px 上仍是 10px / 12px / 13.5px 的可读档位。

同时给交互节点加 **44px 硬下限**（`.action` / `.link` / `.row`），
不再依赖 rpx 换算。

## 3. L3 光核专项

| 检查 | 结果 |
|---|---|
| 四边 alpha 最大值 | **0**（480px 与 96px 资产均如此） |
| 中心 alpha | 255 |
| 非零像素占比 | 71.3%（480px）/ 70.3%（96px） |
| 棋盘格合成 480px | 角点=255 边缘中点=255 中心=(179,139,118) → 无矩形 |
| 棋盘格合成 240px | 角点=255 边缘中点=200（棋盘格本身）→ 无矩形 |
| 棋盘格合成 96px | 角点=255 边缘中点=255 → 无矩形 |
| 缩到 96px 的轮廓 | 保持非对称主体，见 `assets/light-small.png` |

结论：**边缘透明、任意底色可合成、缩放不产生色圈或方块**。未改动造型。

但**窄屏最危险的 rpx 缩字问题已在代码层消除**，且触控热区已有 44px 硬下限。

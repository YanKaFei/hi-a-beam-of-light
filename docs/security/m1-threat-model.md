# M1 威胁模型

**一句话结论：签名证明"谁说的"，不证明"发生过"。**
M1 的全部防御建立在把这两件事分开，而不是假装密码学能证明使用真实。

---

## 1. 四个必须分开的属性

| 属性 | 取值 | 由谁决定 |
|---|---|---|
| 证据等级 | E0–E4 | 既有规则，未改 |
| 签名结果 | VALID / INVALID / UNKNOWN / REVOKED | 密码学校验 |
| 来源类型 | UNSIGNED_CLAIM / SIGNED_SELF_CLAIM / PLUGIN_OBSERVED / INDEPENDENTLY_CORROBORATED | 签发者声明 + 服务端政策 |
| 服务端核准 | 可否计入称号 / 可否激活 / 可否进公共光场 | `POLICY` 矩阵 |

**没有一条路径能仅凭签名把事件升级为公开可信。**

---

## 2. 十个威胁，逐一给结论

| # | 威胁 | 防御 | 是否真正防住 |
|---|---|---|---|
| 1 | 任意客户端伪造 E3 | `/v1/usage/attest` 旧路径仍接受自述；M1 新路径要求签名 | **部分**。旧路径仍开着，是已知遗留，见 §4 |
| 2 | 用户自造密钥伪造使用声明 | **不防**。签名只能证明他持有密钥 | **不防**，由政策兜底：自述类永不可激活 |
| 3 | 复制签名凭证重放 | `(identity_id, id)` 唯一约束 + `credential_consumption` 一次性消费 | **防住** |
| 4 | 盗用他人凭证 | `subject_identity_id` 必须等于调用者；密钥按身份隔离 | **防住** |
| 5 | 关系建立前造证据、之后提交 | 挑战绑定 `transfer_id`，且挑战必须在关系存在后签发；`observed_at` 受服务端时间窗约束 | **防住**（仅限走挑战的激活路径） |
| 6 | 篡改 family / 等级 / 时间 | 签名覆盖全部业务字段；字段在签名输入内 | **防住** |
| 7 | 密钥泄露、撤销、恢复 | `POST /v1/keys/revoke` 立即失效 | **撤销防住；恢复未做** |
| 8 | 同一事件跨多个邀请复用 | 一个 `credential_id` 只能被一个 `transmission_id` 消费（主键） | **防住** |
| 9 | 恶意插件 / 假冒官方插件 | 密钥注册 + 来源分类；未知插件只能拿自述档 | **部分**。无法证明二进制未被修改 |
| 10 | 海量虚假节点操纵光场 | 速率限制 + 每身份每家族去重 + 公共光场只接受 INDEPENDENTLY_CORROBORATED | **目前等于冻结公共光场**（见 §3） |

---

## 3. 三条必须公开承认的能力限制

1. **本地插件永远只是"自述的观察者"。** 它运行在用户机器上，用户可以改它、可以伪造它。
   任何把插件证据说成"已验证的真人使用"的文案都是错的。
2. **注册公钥 ≠ 代码未被修改。** 我们登记的是密钥，不是二进制哈希；也没有可信构建链路。
3. **公共光场实际上没有可信来源。** `INDEPENDENTLY_CORROBORATED` 目前没有任何路径能达到，
   所以公共统计在 M1 之后仍不增长。这是**故意**的：宁可功能受限，也不放松证据。

---

## 4. 已知遗留风险（不在本轮修）

- **旧路径 `/v1/usage/attest` 仍然接受客户端自述的 E3/E4**，只要格式合法。
  它被保留是为了不让现有记录失效。**建议在 M2 前对其加标记或逐步下线**，否则新旧两条路径的可信度不一致。
- **身份恢复没有设计。** 密钥丢失 = 光种丢失。M1 只做了密钥撤销。
- **时间信任**：`observed_at` 由客户端给出，服务端只用它做合理性窗口检查，不能证明真实观察时刻。

---

## 5. 攻击者视角的成本收益

假设攻击者想让自己显得"用过 GPT"：

- 他可以生成密钥、注册、签一条 `SIGNED_SELF_CLAIM`。**成本接近零。**
- 他能得到：本地记录、个人称号计数。
- 他得不到：FIRST_LIGHT 激活、公共光场数字、他人的回响。

**这就是设计意图**：伪造对攻击者没有收益，因为唯一有价值的出口（激活与公共光场）
需要他自己控制不了的东西。

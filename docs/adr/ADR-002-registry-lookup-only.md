# ADR-002 · 模型家族只查表，绝不字符串推断

- **状态**：已采纳，已实现（`crates/light-core/src/registry.rs`），有测试与共享夹具
- **决议来源**：F0 缺口 G-02
- **论证背景**：[01-architecture.md](../01-architecture.md) §4 ADR-002

## 决策

`data/model-registry.v1.json` 是唯一事实来源，它是**数据**，不是代码。

1. 匹配顺序固定：客户端前缀剥离 → 精确别名 → 前缀别名（长者优先）。
2. 每条别名必须声明 `disposition`：`family` / `task_label`。
3. **未命中一律 `UNKNOWN`，不计数、不猜、不折中。**
4. 别名指向不存在的家族、重复别名、空别名 —— 注册表加载即失败。
5. 每次归一化都记录使用的 `registry_semver`。

## 为什么前缀规则不算"推断"

前缀规则是**显式登记的**策展决策（例如 `gpt-` → gpt），写在数据文件里、需要评审、有版本。
"看到字符串里有 gpt 就算 GPT" 才是推断。区别在于：前者可追溯、可回滚，后者不可。

测试中包含反例 `my-gpt-wrapper` 必须不匹配——确保前缀是"以…开头"而非"包含"。

## 后果

- 新模型发布时需要更新注册表（一次数据 PR），而不是让代码去猜。
- 未登记的模型会显示为未知，并在界面上诚实呈现，不会静默变成某个家族。

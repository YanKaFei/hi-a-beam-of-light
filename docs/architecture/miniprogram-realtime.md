# 小程序实时通信评估

## 三个方案

| | 方案 | 依据 | 代价 |
|---|---|---|---|
| A | WebSocket 前台实时 | 小程序支持 `wx.connectSocket`，前台可用 | 后台被挂起，回响可能延迟到下次前台 |
| B | HTTPS 轮询 | 一定可用 | 服务端 QPS 随用户线性增长；"实时"是假的 |
| C | WebSocket + 轮询降级 | 前台 WS，断线/后台转轮询 | 两套代码，但没有额外服务端复杂度 |

## 结论

**推荐 C。** 但**不预先锁死轮询间隔**——间隔应由"回响到达的紧迫度"决定：

- 用户正停在「回响」页：短间隔（如 5s）。
- 用户在其他页：长间隔（30–60s）或仅在前台切换时拉一次。

## 需要实测确认的事

- 小程序切后台后 WS 的存活时长（各基础库版本差异大）；
- `wx.connectSocket` 在弱网下的重连语义；
- 服务端 SSE 是否需要为小程序单独开一个 WS 端点（现有 `/v1/events/stream` 是 SSE）。

**这些都没有在本轮验证**，因为小程序工程尚未获授权启动。本文件是评估，不是结论性设计。

## 2. CSS 选择器完整性测试（新增）

`apps/desktop/tests/layout_selectors.test.mjs`，**9/9 通过**。

- 逐个断言布局关键元素存在：`#v-mine` `#v-give` `#v-paths` `#v-echo` `#btn-give` `#m-veil`
- 导航栏存在且含四个入口
- 每个 section 的 id 必须以 `v-` 开头（防止再次出现 `#mine` 与 `#v-mine` 的漂移）
- **样式表中出现的每个 `#id` 选择器都必须能匹配到真实元素**——这条直接挡住 R1 那类静默失效

写这条测试时踩了一个自己的坑：正则把颜色 `#fff` 当成了 id 选择器，误报失败；
已收紧为「纯十六进制 token 不算选择器」。

不允许用更宽泛的选择器掩盖失效规则——测试断言的是**精确 id 命中**，不是"能选中点什么"。

## 3. 安静模式 CPU 对照（A/B/C）

同一进程、同一窗口（720×560）、同一页面（我的光）、同一采样方法（`perf` 自测 1.5s 窗口）。
策略通过 `html[data-ov]` 运行时切换，避免三份构建带来的差异。

| 策略 | 中位数 | 范围 | 5 次采样 | RSS |
|---|---|---|---|---|
| A `overflow-y:auto` | **0.0017%** | 0.0014–0.0180 | 0.0015 / 0.0021 / 0.0014 / 0.0017 / 0.0180 | 96.8 MB |
| B `overflow-y:hidden` | 0.0038% | 0.0013–0.0139 | 0.0017 / 0.0129 / 0.0139 / 0.0013 / 0.0038 | 97.3 MB |
| C `smart`（仅溢出时启用） | **0.0015%** | 0.0011–0.0159 | 0.0015 / 0.0039 / 0.0011 / 0.0159 / 0.0013 | 97.4 MB |

### 结论与自我更正

**三者在同一量级，`overflow-y:auto` 不是 R1 那次 0.112% 的原因。**

我上一轮把 0.015% → 0.112% 归因于 `overflow-y:auto`，依据只是"同一次改动里加了它"——
这是相关性，不是因果。本轮对照实验否定了那个归因。

R1 那次 0.112% 更可能来自测量时的环境差异：那一次采样窗口内，面板刚被 resize 过，
WebKit 正在重建合成层。**这一点我没有再做实验证明，因此只是"未被证实的解释"，
不是结论。**

采用 **C（smart）**：中位数最低，且只在真正溢出时才付出滚动成本，
兼顾了正确滚动与可访问性。

### 仍然存在的偏差
三个策略的采样里都有 0.013–0.018 的离群值，说明静息态存在周期性唤醒（大概率是面板
每 6s 的可见页轮询）。要不要把轮询也改为事件驱动，是下一轮的事，本轮不动。

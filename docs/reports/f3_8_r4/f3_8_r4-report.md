## 1. 扫描状态契约

### 1.1 修改前

`ScanStatus` 只有四个值：`Ok / NotAuthorized / ClientNotFound / Failed`。
UI 只读 `settings.scan_enabled` 一个布尔值，所以**任何失败都显示成「扫描授权已关闭」**。

两处具体缺陷：

1. **原因不可区分**：系统拒绝访问与数据源不可读都落在 `Failed`。
2. **失败会清空记录**：`light_payload` 的 `verified_families` 取自最近一次扫描结果，
   失败时该值为 `None` → 界面显示 0 个家族，**已核验记录凭空消失**（数据还在本地库里）。

### 1.2 修改后

`ScanStatus` 增加两个值，共六种结局：

| 状态 | 含义 | 界面文案 | 下一步 |
|---|---|---|---|
| `NotAuthorized` | 未授权 | 扫描授权已关闭 | 开启扫描 |
| — | 已授权未扫描 | 已授权，尚未扫描 | 扫描一次 |
| — | 本次未确认 | 本次扫描未获授权 | 扫描一次 |
| `ClientNotFound` | 未发现客户端 | 未找到支持的 AI 客户端 | 重新扫描 |
| `AccessDenied` | 系统拒绝 | **系统拒绝了访问** | 重试 |
| `Unreadable` | 数据源不可读 | **数据源暂时无法读取** | 重新扫描 |
| `Ok` + 0 | 扫描成功无记录 | 已扫描，暂无可信使用记录 | 重新扫描 |
| `Ok` + N | 扫描成功有记录 | 已扫描 | 重新扫描 |

分类依据：读取错误消息里是否含 `operation not permitted` / `permission denied` / `access denied`。

**不泄露**：原始异常与路径只写 `eprintln!` 给开发者；`reason` 是固定短句。
`ClientNotFound` 原本文案含 `~/.codex`，已去掉。

**不清空**：`light_payload` 在某次扫描没有结果时回退到本地库里的已核验家族。

### 1.3 实测（运行中读取 DOM 文本）

```
off        → 扫描授权已关闭
no_client  → 未找到支持的 AI 客户端 ｜ 安装后可以再试一次
primary    → 扫描一次
```

## 2. 我的光（业务一致性已修正）

- 顺序：称号 → 可信家族数 → 模型详情 → 主操作。
- **称号与数字都来自服务端**，页面不重算，因此不可能出现"3 个家族 + 启迪者"这种矛盾。
  实测三个状态：

  | 状态 | 称号 | 数字 | 主操作 |
  |---|---|---|---|
  | 未核验 | 寻光者 | 0 | **开始点亮** |
  | 1 个家族 | 初明者 | 1 | 传一束光 |
  | 2 个家族 | 启迪者 | 2 | 传一束光 |

- 0 家族时主操作是「开始点亮」（走扫描授权），不是"传光"。
- 主操作是 36px 高的实心按钮，**按文字宽度**，不再横贯整页。

## 3. 传光

- 文案已改：**「传光不会减少你的光。对方接收后，你们之间会出现一条光路。」**
  原句暗示"分享会失去"，与产品语义相反。
- 十个状态合并为一张表（idle/creating/waiting/received/learning/activated/
  acknowledged/expired/cancelled/failed）+ 未连接。**没有计时器推进状态**，`phase` 只由服务端写入。
- 未连接时：显示说明与「重试连接」，二维码板 **不显示**（不给假二维码）。
- 二维码板是唯一的独立表面（白底、1px 边、16px 静区）。

## 4. 光路

三个维度各自有名字与一句解释：已激活 / 待激活 / 我收到的。
空态说明这里记录什么、下一步做什么。列表是时间行，没有关系网装饰。
数字口径为**匿名光种节点**，页面不出现"真人"字样。

## 5. 回响

保留原句。有事件时显示时间与历史（1px 细线分隔），无事件时为一句弱化文字。
不再用灰球占位。

## 8. 施工中发现并修掉的三个真实缺陷

1. **`#app` 网格只有两行却有第三个子元素** → `main` 落进隐式行、高度塌成 0，整页内容不渲染。
   这是截图空白 1400×1000 的直接原因。
2. **模型行显示 `undefined`**：`light.families` 是字符串数组，页面按对象取 `f.name`。已改为兼容两种形状。
3. **扫描状态会过期**：`get_settings` 只在启动时读一次，扫描后 UI 仍显示「已关闭」。已加入可见页轮询。

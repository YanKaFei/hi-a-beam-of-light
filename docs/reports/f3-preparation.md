# F3 传光开发准备清单

F2 已把「本机可见的光」做完。F3 要做的是**让光在人与人之间传出去**。
本清单只列开工前必须知道、必须先定的事。

---

## 1. 已完成、可直接复用的部分

| F1/F2 产物 | F3 怎么用 |
|---|---|
| `light-core::transmission::Session` | 传光状态机已实现并有 13 项测试，服务端直接复用同一转移表 |
| `packages/protocol/schemas/*.json` | 11 个线格式契约已冻结，`/transmissions` 系列已在其中 |
| `UsageAttestRequest` 的 `deny_unknown_fields` | 服务端接收端不必再写"拒绝多余字段"的校验 |
| `ADR-008` 的三条取证通路 | 移动端/小程序接入的可信路径已定 |
| `ADR-011` 双闸门 | 服务端只需信任客户端已判定的 E3/E4，并用 DB 约束二次兜底 |

**未复用、必须新写的**：Hono 服务、Postgres 迁移、二维码与接收页、SSE。

## 2. 开工前必须先解决的三个硬前提

### 2.1 HTTPS 域名（阻塞 A06）
接收页必须是 `https://` 才能被扫码打开、才能作为 NFC 的 NDEF 载荷。
需要：域名 + 证书 + 一个可公网访问的部署点。
**没有它，F3 的验收（A06 二维码接收）无法开始。**

### 2.2 服务端运行时（阻塞 F3 全部）
F1 定的是 Hono + Postgres，测试用 PGlite。需要：
- 一台能跑 Node 的机器或托管平台
- Postgres 16+ 实例（或先用 PGlite 单实例验证，但不可用于生产）
- 对象存储（导出包，可延后）

### 2.3 品牌名（阻塞对外文案）
接收页会出现「第一束光」以外的品牌文字。ADR-006 要求品牌串单点配置，
`packages/visual-system/brand.json` 尚未创建。**F3 开始前必须建**。

## 3. 服务端实现顺序（建议）

| 顺序 | 任务 | 依赖 | 验收 |
|---|---|---|---|
| 1 | Postgres 迁移（照抄 `docs/03-data-model.md` 的 DDL） | 无 | PGlite 跑通同一份迁移 |
| 2 | 签名鉴权 + nonce 防重放 | 无 | 重放用例返回 401 |
| 3 | `/usage/attest`（含 `unique(identity,family)` 去重） | 1,2 | 连发 10 次只 +1 |
| 4 | `/transmissions` 全套 + 状态机 | 1,2 | 13 项转移用例 |
| 5 | Web 接收页 `apps/web` | 2.1 | 手机扫码可拒绝、可接受 |
| 6 | 激活与回响 | 4,5 | A09/A10 |
| 7 | `/privacy/*`（导出、撤回） | 1..6 | A12 |
| 8 | SSE 光场 | 1 | 限频 ≤2/min、断线续传 |

## 4. 必须先定的产品决策（阻塞数据模型）

| 决策 | 影响 | 我的建议 |
|---|---|---|
| 光种何时注册到服务端 | 决定身份表与恢复流程 | 首次授权贡献时注册，之前纯本地 |
| 撤回后 `light_edge` 对方一侧怎么显示 | 决定边表结构 | 显示为「一条已撤回的匿名边」 |
| 传光称号的 24h 冷却是否可配置 | 决定聚合窗口 | 可配置，默认 24h |
| 地区由用户选择还是 IP 粗粒度 | 决定 `region_source` | 用户主动选择优先，IP 仅作默认建议 |
| k-匿名阈值 20 是否调整 | 决定光场粒度 | 先 20，观察真实分布后再定 |

## 6. 一句话

F2 证明了「光可以真实地亮起来」，而且能说清为什么亮。
F3 要证明的是「光可以真实地传出去」，而且**收到光不等于学会**——
那条界限（`RECEIVED ≠ ACTIVATED`）已经在状态机里，F3 只需要把服务端接上去，
不要为了流程顺畅把它放松。

# F4 全球光场准备方案（草案）

F3 结束时，服务端已有 12 张表与一个 `/v1/field/summary` 占位接口。
F4 要做的是把这些匿名事件变成**可信、可解释、不泄露个人**的公共景观。
本文件只列必须提前定的事，不是实现计划。

---

## 1. F3 已经给 F4 留下的基础

| 已有 | 状态 |
|---|---|
| `light_edge` 可聚合（不含内容） | 可用 |
| `outbox_event` 作为事件源 | 可用 |
| `region_code` 字段（尚未启用） | 需补 |
| `/v1/field/summary` 形状 | 已按三个独立指标定义 |
| SSE 通道与限速机制 | 可用，直接复用 |

---

## 2. F4 必须先解决的四件事

### 2.1 地区从哪里来（隐私关键）
F3 没有采集任何位置。F4 需要：
- **优先**：用户在设置里主动选择"大致区域"（省级或城市级）；
- **次选**：IP 粗粒度推断，且必须告知并允许关闭；
- **禁止**：经纬度、街道、精确到街区。

数据库已有 `identity.region_code` / `region_source` 的定义（见 `docs/03-data-model.md`），
F4 落地时用同一套行政区码表，不存坐标。

### 2.2 k-匿名阈值与抑制
服务端 `region_aggregate` 必须**没有任何 identity 列**，且：
- `contributing_nodes < 20` → `suppressed = true`，展示上级区域；
- 阈值放配置，不硬编码；
- 小规模事件做时间窗合并，避免"根据时间和位置反推是谁"。

### 2.3 三个数字绝不能合并
产品文档 §8.2 明确：
- 累计激活节点（自愿参与且有一次可信激活）
- 当前在线实例（短时心跳，≠ 自然人）
- 今日新增激活事件

`FieldSummary` 已经是四个各自带 `window` 与 `note` 的 `FieldMetric`，
**没有**一个可以合并的 `total` 字段。F4 不要新增。

### 2.4 可视化不得造假
- 无数据时显示空状态；
- 不重播旧事件当新事件；
- 弱网标注"缓存于 XX:XX"；
- 艺术化连线必须与真实关系链视觉可区分。

## 3. 前端资源策略（F2 已定，F4 必须遵守）

| 约束 | 来源 |
|---|---|
| 光点用 Canvas2D，不用 WebGL | F2 性能结论：WebGL 上下文长驻会破坏 CPU/内存预算 |
| WebGL 只在光场视图打开时创建 | 同上 |
| 节点 > 3000 才考虑 WebGL | `docs/01-architecture.md` §2.6 |
| 不得在桌面光点阶段预加载光场资源 | 授权书 §12 明确要求 |

F2 实测基线：空闲 0.031% CPU / 112.7 MB RSS。F4 加入光场后**必须重测**，
尤其内存（余量只剩约 7 MB）。

---

## 4. 建议的 F4 实施顺序

1. 区域选择 UI + `identity.region_code` 写入（无聚合）
2. `region_aggregate` 表 + 定时聚合任务（离线跑，可重算）
3. 抑制逻辑与"上级区域"回退
4. `/v1/field/regions`（离散密度档，无坐标）
5. SSE 光脉（复用 F3 通道，限频 ≤2 次/分钟）
6. 光场可视化（Canvas2D 起步）
7. 静观模式（无身份观看）

---

## 5. F4 之前必须回答的产品问题

| 问题 | 影响 |
|---|---|
| 默认展示到哪一级（国家 / 省 / 市） | 阈值与视图 |
| 是否允许"我在的城市"这类文本搜索 | 可能被用于定位推断 |
| 光脉的默认频率与静音默认值 | 体验与骚扰风险 |
| 观看者是否需要接受任何条款 | 隐私政策 |

---

## 6. 一句话

F4 的难点不是地图，是**在"让人看见正在发生的事"和"不让人被看见"之间找到线**。
F3 已经把这条线画在了数据模型里（聚合表无 identity 列），F4 不要越过去。

# 真实联调环境准备清单（F3 → 生产）

当前服务只在 `127.0.0.1` 上运行，用 PGlite，无 TLS。这不是生产形态。
本清单列出把 F3 变成"别人手机真的能扫码"所需要的一切。

---

## 1. BLOCKED：需要你另行批准的外部条件

| 项 | 为什么必须 | 不做会怎样 | 授权状态 |
|---|---|---|---|
| **HTTPS 域名** | 接收页必须 https：扫码、NFC NDEF、浏览器安全上下文都要求 | 二维码只能在本机打开；NFC 无法写 | 未批准购买 |
| **公网部署** | 别人的手机要能访问 | 只有自己能测 | 未批准发布 |
| **TLS 证书** | 同上 | — | 随域名 |
| **生产 Postgres** | PGlite 是单进程 WASM，不适合并发 | 多实例会各写各的 | 未批准开通 |
| **真实设备**（iOS / Android） | 真机扫码与 NFC | 只能测服务端 | 缺 Xcode/SDK |
| **NFC 标签与读写器** | 实体光石 | NDEF 只能软件层验证 | 未采购 |
| **Apple Developer Program** | iOS 签名、关联域 | 无法分发 | 未批准 |

**这些一条都没有绕过。** 本轮所有"通过"的证据都在本地闭环内。

---

## 2. 拿到域名后的部署步骤（按顺序）

1. **DNS**：`api.<domain>` → 服务器；`<domain>` 根域用于接收页（可同机）。
2. **证书**：Let's Encrypt 或托管平台自动证书；确认仅 TLS 1.2+。
3. **数据库**：Postgres 16+，执行 `services/api/migrations/001_init.sql`（与 PGlite 同一份）。
4. **服务**：`FL_PUBLIC_BASE_URL=https://api.<domain>`、`FL_PORT=8787`，前置反向代理。
5. **反向代理要点**：
   - SSE 路径必须关闭缓冲（`proxy_buffering off`），否则回响会延迟到连接结束
   - `proxy_read_timeout` ≥ 60s（心跳 15s）
   - 不要缓存 `/v1/*`
6. **健康检查**：`GET /v1/field/summary` 应 200。
7. **冒烟**：用 `services/api/test/support/client.mjs` 走一遍 T1→T7。
8. **再验一次"收到的光不算成功"**：在真实环境里重跑 T4/T5，别只在本地信过。

---

## 3. 反向代理与安全加固（上线前必须完成）

| 项 | 要求 |
|---|---|
| 速率限制 | 网关层再加一层（应用层已有），至少覆盖 `/v1/transmissions` 与 `/v1/usage/attest` |
| 请求体上限 | 8 KB（我们的最大请求远小于此） |
| 日志 | **不记录** `/t/{token}` 的完整路径（令牌是秘密）；记录前做截断 |
| 第三方脚本 | 接收页**不引入任何**分析 SDK（授权书 §5 明确要求） |
| Referrer | 接收页已设置 `referrer: no-referrer` |
| HSTS | 上线后启用 |
| 备份 | 每日；恢复演练一次 |

## 4. NFC 光石的真实测试步骤（拿到标签后）

1. 用读写器把 `https://<domain>/n/<tagId>` 写入 NTAG215（NDEF URI 记录）。
   - **只写公开 URL**；不写任何密钥、身份或权限。
   - 长度检查：`maxUrlBytes: 128`（见 `brand.json`）。
2. 用 iPhone / Android 各触碰一次，确认打开接收页。
3. 在**没有活跃邀请**时触碰：应显示"没有开启的传光"，且数据库里
   `transmission` / `light_edge` 计数不变（这就是 T10 的真机版）。
4. 在**有活跃邀请**时触碰：应进入接收页，但仍需接收者主动点"接收"。
5. 复制标签内容到另一个标签，重复扫描：应表现一致（标签本来就不是凭证）。
6. 多人同时扫描同一标签：只有第一份能建立会话，其余 `SESSION_TAKEN`。

## 6. 一句话

技术上，把 `FL_PUBLIC_BASE_URL` 指向一个真实 HTTPS 域名，这套服务就能被别人扫码使用。
**但在没有你批准域名与部署之前，它不会出现在公网上**——这是授权边界，也是安全边界。

## 1. 用例 J：位置恢复

### 1.1 结论
**不是代码缺陷，是锁屏环境。** F3.5 那次失败时，窗口服务器不接受 `set_position`：
磁盘里存着 (430,360)，窗口却停在默认居中 (1446,916)，重启后读回同一个居中值。

### 1.2 解锁后的复现与加固
不依赖 E2E，单独写了一段确定性实验：

```
A start        : (1446,916)   disk: null      ← 首次运行的默认居中
move           : ok
B after move   : (430,360)    disk: (430,360) ← 已落盘
C after reboot : (430,360)    disk: (430,360) ← 恢复正确
```

再连做三次重启：

```
restart 1: (430,360)
restart 2: (430,360)
restart 3: (430,360)
```

越界位置的安全修正：

```
move (9000,4200) → 报 (9000,4200)
重启后          → (1446,916)   在其显示器范围内 → 修正成立
```

### 1.3 逐条核对你列出的怀疑点
| 怀疑点 | 实际 | 结论 |
|---|---|---|
| 保存与恢复同一坐标空间 | 两侧都是 `PhysicalPosition` / `Px` | 一致 |
| 多显示器与缩放 | 单显示器 scale=2；`monitor_rects` 用物理矩形 | 一致 |
| macOS Y 轴 | 全程物理坐标，未做翻转变换 | 无问题 |
| 运行时窗口尺寸变化 | 光点窗口尺寸固定 264 | 无关 |
| 恢复位置与设置尺寸的时序 | 先 `place` 再 `show` | 正确 |
| 启动与 WebView 初始化时序 | 位置在窗口配置阶段设置，早于页面加载 | 正确 |
| 默认居中覆盖保存值 | 仅当 `settings.position == None` | 正确 |
| 显示器布局变化时的边界修正 | `geometry::place` 有 Rule 1 重叠检查 | 有效 |

**没有改任何断言。** J 现在通过是因为它真的通过了；上面三段实验是额外的加固证据。

## 4. 性能与安全回归

### 4.1 扫描授权（P0，保留）
`scan::authorize(开关 且 本次确认)` 仍是唯一入口；`complete_transfer` 仍然完全不扫描。
`tests/f3_6_scan_auth.py` **5/5**，断言的是**实际读取次数**：
拒绝时 0 次，确认时恰好 1 次。

### 4.2 性能
视觉改动后重测（`target/f36r1-perf.json`）：

| 指标 | F3.5 | **R1** | 目标 |
|---|---|---|---|
| 空闲（动画中）CPU 均值 | 0.048% | **0.040%** | ≤0.10% |
| 空闲 CPU 峰值 | 0.074% | **0.064%** | ≤1% |
| 安静模式 CPU | 0.033% | **0.015%** | — |
| RSS | 113.2 MB | **113.5 MB** | ≤120 MB |
| 30s 增长 | — | **0.0 MB** | 无增长 |
| 扫描耗时 | 2 ms | **2 ms** | — |
| 退出残留 | 无 | **无** | — |

比 F3.6 首次测量还低（0.053% → 0.040%），因为光点改为双画布后每帧只合成两张位图。

### 4.3 其它
- SSE/轮询：未配置服务端时面板不启动 SSE 监听；仅在对应用户可见页签存在 6s 轮询。
- release 构建：`strings` 检查默认构建**不含** `FIRSTLIGHT_CONTROL_SOCKET`。
- F1–F3.5 业务测试：全绿（§5）。

# 传光与真实地图 · 更新说明

## 交付范围

本次更新浏览器验收版，不代表微信小程序和手机 App 已正式支持 NFC 或跨机传光。工作副本为 work/first-light，桌面原仓库未覆盖。扫码接收记录保存在独立 SQLite 中，不写入原正式 API 的身份、可信证据或激活记录。

## 产品判断

二维码和 NFC 是同一邀请的两种入口，不能合称为一种“NFC 二维码”。推荐扫码为主，碰 NFC 卡/贴纸为补充。普通手机之间互碰不作为跨 iOS/Android/微信的默认承诺。

推荐正式链路：生成邀请 → 扫码或碰标签打开 → 对方明确接收 → 两端收到服务端状态 → 播放传光动画 → 开始实际 AI 学习与配对 → 有使用证据后再点亮。

本轮自动化实现到“邀请接收”，不把一次扫码计为实际使用 AI。触发两端动效的是 RECEIVED 状态，不是生成二维码或打开链接本身。独立“预览传光动效”按钮明确标为预览，不产生邀请和计数。

## 可验收功能

- 创建真实 URL 二维码，链接对应本地服务邀请；15 分钟失效，可撤销。
- 同一邀请只允许一个其他访客接收；自己接收被拒绝；同一接收者重复点击幂等。
- 发起端轮询接收状态，收到接收记录后触发动画；接收端成功 POST 后触发动画。
- 3.6 秒传光动效：手机轮廓 → 金色/珊瑚/淡紫光束与粒子尾迹沿弧线飞出 → 接收端光晕/波纹。主光不会因分享消失；支持减少动态偏好。
- 世界/中国/上海视图，世界和中国按边界适配显示范围；真实 OpenStreetMap 底图，可缩放/拖动。
- 点选位置生成私人标注，保存于浏览器 localStorage，可在标注弹窗删除；最多 100 个。地图已有光点仍为演示，不表示实际附近用户。
- 底图请求失败时显示状态，可点击“重新加载底图”。

## 启动与跨机限制

用本目录“启动测试页.command”，或执行：

```sh
python3 preview_server.py --port 8896
```

默认只绑定 127.0.0.1。二维码指向本机时，另一台手机扫码无法访问；需要双方共同能访问的部署地址才能做真实跨手机联调。这次没有把服务暴露到公网或局域网。

`--public-base https://你的测试域名` 可以让二维码使用事先准备好的 HTTPS 测试入口，但这只是 URL 配置，不会自动部署、设置证书或打通网络。

访客身份是预览用 HttpOnly/SameSite Cookie，不是微信登录；原 Node 服务签名接口没有被降级。浏览器直接打开 index.html 只能检查部分 UI，完整二维码邀请需要运行 preview_server.py。

## NFC 限制与下一步

当前 NFC 按钮提供流程说明，没有写标签、没有声称硬件读取成功。iPhone 背景读标签通常弹通知，用户需要点击；网页 NFC 不支持通用 peer-to-peer 手机互碰。实体 NFC 卡正式版应写可撤回的稳定卡片 URL，再查当前可用邀请，不能把 15 分钟即过期的链接永久印在卡里。

在微信中打开指定小程序的 URL Link/Scheme 与标签能力还需接入对应账号配置，并在真机验证；本轮未获得可验证的微信官方 NFC 文档全文，未以非官方教程承诺其兼容性。

中国正式服务建议评估高德/腾讯 SDK 及应用 Key。当前是 OSM 开发底图，不等于完成国内正式地图服务配置，也没有更改或自行重绘行政边界。开发验收时中国视图曾有部分瓦片加载失败，上海底图实际正常加载。

## 验证

- Python HTTP 集成测试 4 项通过：两访客接收/幂等/第三方抢占/双方计数，撤销所有权，过期拒绝，跨来源写入拒绝。
- 动效有限坐标测试 1 项通过（300、390、1200 宽度与普通/减少动态）；原开场 2 项通过。
- JavaScript 语法与 Python 编译检查通过。
- 浏览器实测：生成二维码、撤销邀请、传光预览、世界与中国视图切换、上海添加标注、标注详情与删除。
- 未做：真实手机扫码、NFC 标签写入/读取、真实微信登录、公开附近用户、正式跨设备互操作。
